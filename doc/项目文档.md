## 0. 文档约定

### 0.1 命名与格式约定

| 约定项 | 规则 | 示例 |
|---|---|---|
| 路径参数 | 小写 + 下划线 | `<table_id>`、`<record_id>` |
| 请求字段 | 小写下划线（snake_case） | `expected_updated_at` |
| 响应字段 | 小写下划线（snake_case） | `created_at` |
| 主键 | UUID v4 字符串 | `3f2b8c1e-9a4d-4f6b-8e2a-1c5d7f9b0a34` |
| 时间 | ISO 8601，UTC 带时区 | `2026-11-10T14:32:07.123456+00:00` |
| 日期 | `YYYY-MM-DD` | `2026-11-10` |
| 日期时间（字段值） | `YYYY-MM-DDTHH:mm:ssZ` | `2026-11-10T06:30:00Z` |
| 金额/数值 | JSON number；精度由字段 `config.precision` 决定 | `1299.5` |
| 空值 | `null`（部分历史字段可能是 `{}` / `[]`） | — |

### 0.2 类型标注约定

| 标注 | 含义 |
|---|---|
| `uuid` | 36 位 UUID 字符串 |
| `string(n)` | 字符串，最大长度 n |
| `integer` / `number` / `boolean` | JSON 数值 / 布尔 |
| `enum(a,b)` | 枚举，取值仅限列出的字面量 |
| `object<K,V>` | JSON 对象 |
| `array<T>` | JSON 数组 |
| `ts` | ISO 8601 时间戳字符串 |
| `readonly` | 服务端生成，客户端传入将被忽略 |

### 0.3 必填列语义

数据结构表格中的「必填」列：

- **是**：创建时若不传，请求失败或返回 400 / 422。
- **否**：可省略，服务端使用默认值。
- **只读**：由服务端生成（`id` / `created_at` / `created_by` 等），客户端传入无效。

## 1. 项目概述

### 1.1 定位

SmartTable 是可私有化部署的「多维表格 + 轻应用平台」。核心数据模型为五层：

```
Base（工作区）→ Table（数据表）→ Field（字段）/ View（视图）/ Record（记录）
                                  ↘ Dashboard（仪表盘）/ Document（文档）/ Workflow（工作流）
```

在此之上提供：27+ 字段类型、8 种视图、公式引擎（76 个函数）、跨表关联与查找、仪表盘、富文本文档、自动化工作流、Webhook、插件体系、第三方应用 OAuth2 接入、完整 RBAC 与审计。

### 1.2 能力矩阵

| 能力域 | 关键能力 |
|---|---|
| 数据建模 | 字段动态增删、32 种字段类型、字段类型转换（含丢失性转换二次确认） |
| 数据呈现 | 表格 / 分组 / 看板 / 日历 / 甘特 / 表单 / 画廊 / 列表 视图，筛选·排序·分组·列冻结 |
| 计算能力 | 公式字段（跨表整列引用、`CurrentValue` 条件聚合）、Lookup 查找字段、关联字段 |
| 规模能力 | 流式加载（首屏 200 条 + 后台 3 并发补页）、canvas 虚拟滚动、IndexedDB 本地库 |
| 协作能力 | 成员 RBAC（5 级）、Base / 表 / 表单 / 仪表盘 4 类分享、Socket.IO 实时协作（可选） |
| 自动化 | 事件触发 / 定时触发 / 记录时间触发、10 类节点、版本快照与回滚、Webhook 投递与重试 |
| 扩展性 | UI 插件（iframe 沙箱）、脚本插件（受限子进程 + RPC 代理）、插件两级配置与回滚 |
| 开放性 | 开放 API（OAuth2 客户端凭证 + scope）、应用审计日志 |
| 可运维性 | 三形态部署（源码 / Docker / EXE）、Alembic 四层迁移、结构化日志与 request_id 全链路追踪 |

### 1.3 架构总览

```
┌──────────────────────────────────────────────────────────────┐
│ 表现层  Vue 3 SPA（Hash 路由）                                 │
│  Base 工作台 / 8 类视图 / 对话框 / 仪表盘 / 文档编辑器          │
├──────────────────────────────────────────────────────────────┤
│ 状态层  Pinia Stores（tableStore 为中枢）                      │
│ 本地读模型  Dexie(IndexedDB) 13 张表                           │
│ 接口层  services/api/* → api/client.ts（拦截器）               │
├──────────────────────────────────────────────────────────────┤
│ 接入层  Nginx :80（静态 / /api 反代 / /socket.io / /uploads）   │
├──────────────────────────────────────────────────────────────┤
│ 应用层  Flask + Eventlet :5000                                 │
│  蓝图 31 个 → 服务 52 个 → 模型 26 个                          │
│  横切：JWT · RBAC · 限流 · 审计 · i18n · 统一响应 · 错误处理器  │
├──────────────────────────────────────────────────────────────┤
│ 数据层  PostgreSQL / SQLite · Redis（可选）· 本地文件系统       │
└──────────────────────────────────────────────────────────────┘
```

关键设计约束（理解全文的前提）：

1. **记录值以 JSON 文档存储**：`records.values` 是 `{field_id: value}` 的对象，字段结构存放在 `fields` 表，不做物理列。
2. **计算后置**：公式、查找、关联均读时计算，结果通过 `computed_values` 或覆盖 `values` 返回，不落冗余列。
3. **筛选在前端**：后端记录列表接口只支持分页与关键词搜索；视图的 `filters / sorts / group_bys` 由前端消费。
4. **能力可缺省**：Redis、实时协作、邮件、对象存储、第三方登录均为可选，缺失时功能降级而非报错。

### 2.2 逐模块说明

#### 2.2.1 认证与用户

- **职责**：注册、登录、令牌签发与刷新、登出（单设备 / 全设备）、邮箱验证、找回密码、验证码、当前用户信息与改密、Gitee Star 校验（演示环境）。
- **核心机制**：
  - Access Token 默认有效期 86400 秒（`JWT_ACCESS_TOKEN_EXPIRES`），Refresh Token 30 天。
  - 令牌撤销：`TokenBlocklist` 表（jti 黑名单）+ 缓存中的 `user_token_version`（支持“退出所有设备”）。
  - 第三方应用令牌撤销走 Redis 集合 `oauth:revoked_jti`（O(1) 判定）。
- **约束**：登录失败次数与验证码有独立限流；密码强度规则由系统配置动态下发；`captcha` 是否必填取决于系统配置。

#### 2.2.2 Base 与成员

- **职责**：Base 的 CRUD、收藏、复制、成员管理（单个 / 批量增删改）、所有权转移。
- **权限模型**：`MemberRole` 五级，等级比较见 [4.4 枚举字典](#44-枚举字典)。Base 所有者由 `bases.owner_id` 直接判定，不依赖成员表。
- **约束**：`(base_id, user_id)` 唯一；Base 名称 ≤100 字符；删除 Base 级联删除其下所有表 / 记录 / 视图 / 仪表盘 / 工作流。

#### 2.2.3 数据表与文件夹

- **职责**：表 CRUD、排序、复制、文件夹（单层分组）CRUD。
- **约束**：`tables.primary_field_id` 为指向 `fields` 的外键（`use_alter`，避免循环依赖）；`folder_id` 可空，无 DB 级外键（历史原因，删除文件夹时需应用层置空）。
- **复制语义**：复制表会复制字段定义与记录，不复制视图之外的分享关系。

#### 2.2.4 字段系统

- **职责**：字段 CRUD、排序、复制、类型查询与转换、字段校验、关联字段（建立 / 修改 / 删除 / 列出）。
- **约束**：
  - 字段名 ≤100 字符；`type` 必填。
  - 创建字段需要 `MemberRole.ADMIN` 及以上；纯表分享用户禁止管理字段。
  - 丢失性类型转换（如文本 → 数字）需二次确认：首次返回 400 + `error=lossy_conversion_requires_confirmation`，带确认标志重试。
- **关联字段**：`POST /api/fields/link` 建立 `LinkRelation`，支持 `one_to_one / one_to_many / many_to_one / many_to_many` 与双向关联。

#### 2.2.5 记录与主从表

- **职责**：记录 CRUD、批量操作、搜索、公式试算、变更历史、关联值读写、关联记录详情、子记录创建（主从表）、树形记录。
- **关键语义**：
  - 创建时若未提供某字段值，自动应用字段默认值（含动态 `now`）；自动编号字段由 Redis 原子计数器生成（Redis 不可用时回退加锁扫表）。
  - 每次写入生成 `RecordHistory`（创建存全量快照，更新存差异）。
  - 删除为软删除（`is_deleted=true`），删除主记录会级联处理自关联的子记录。
  - 写入后发布 `workflow_event_bus` 事件并广播 Socket.IO（若启用）。
- **权限**：读需 `VIEWER`；写需 `EDITOR`（表分享用户需 `editor` 角色）。
- **限流**：写操作 100 次/分钟，批量写 50 次/分钟。

#### 2.2.6 视图系统

- **职责**：视图 CRUD、复制、排序、设默认、类型清单、树形记录、自动创建父字段。
- **配置载体**：`filters`（数组）、`sort_config`（数组）、`group_config`（对象，含 `group_bys`）、`field_visibility`、`hidden_fields`、`frozen_fields`、`field_widths`、`form_config`。
- **约束**：`type` 为 8 种枚举之一；表内可有多视图但仅一个 `is_default`。

#### 2.2.7 公式与查找

- **公式**：`FormulaService` 将公式解析为 AST 求值，支持 `{字段}`、`[表名].[字段名]` 整列引用、`CurrentValue` 惰性遍历、76 个内置函数（数学 18 / 文本 14 / 日期 15 / 逻辑 16 / 统计 13）。
- **查找**：`LookupService` 支持 7 种操作符 + AND/OR、8 种聚合（原值 / 去重 / 去重计数 / 求和 / 计数 / 平均值 / 最大值 / 最小值）。
- **约束**：跨表整列引用只能引用原始值字段（公式 / 查找 / 关联字段不可被引用）；表名与字段名不区分大小写；表 / 字段重命名后公式需手工更新。

#### 2.2.8 仪表盘

- **职责**：仪表盘 CRUD、组件增删改、布局保存、复制、设默认、分享。
- **组件类型**：前端注册表 `widgetRegistry` 定义（bar / line / pie / number / table / area / scatter / radar / funnel / gauge / clock / date / marquee / kpi / realtime）。
- **布局**：网格布局，`position_x / position_y / width / height` 为网格单位（默认 12 列）。

#### 2.2.9 文档

- **职责**：文档 CRUD、版本历史（创建 / 查看 / 恢复 / 删除）、PDF 导出与下载。
- **内容格式**：`content_format` 为 `delta`（Quill Delta）或 `markdown`。
- **并发控制**：`PUT /api/documents/{doc_id}` 支持 `expected_updated_at`，不一致返回 **409**（秒级精度比较）。

#### 2.2.10 工作流

- **职责**：工作流 CRUD、节点与触发器保存、发布 / 暂停 / 恢复、版本快照、克隆、实例查询、手动触发、脚本节点测试、模板库。
- **执行模型**：事件总线（单例，daemon 线程派发）→ 引擎（`ThreadPoolExecutor(max_workers=10)`）→ 从触发节点沿 `next_nodes` 串行推进。
- **节点类型**：`trigger / condition / webhook / loop / find_records / send_email / update_record / create_record / trigger_webhook / script / notify / approval / action(兼容)`。
- **触发类型**：`record_created / record_updated / field_changed / manual / specified_time / record_time_reached`。
- **安全阈值**：触发链最大深度 3（防环）；单记录 Redis 锁 30 秒；单站内信节点最多 200 个接收人。

#### 2.2.11 Webhook

- **职责**：Webhook 配置 CRUD、引用检查、连通性测试、投递记录、重投递。
- **配置项**：名称、URL、HTTP 方法、请求头、请求体模板、最大重试次数、重试间隔。
- **约束**：被工作流引用的 Webhook 不可删除（`error=webhook_in_use`）；URL 需符合格式校验。

#### 2.2.12 分享与实时协作

- **四类分享**：
  - Base 分享（`BaseShare`）：整库链接分享，`view` / `edit` 权限，可设过期时间与访问次数上限。
  - 表分享（`TableShare`）：单表 + 成员角色，支持 token 加入。
  - 表单分享（`FormShare`）：公开填单，支持验证码、成员选择器、提交记录。
  - 仪表盘分享（`DashboardShare`）：公开看板，支持访问码与过期。
- **实时协作**：Socket.IO 房间以 `base_id` 为单位，提供在线状态、视图同步、单元格锁定（Redis `SETNX` + 60 秒 TTL）、乐观并发冲突提示、离线队列重放。可通过 `GET /api/realtime/status` 探测可用性。

#### 2.2.13 插件

- **形态**：`ui`（iframe 沙箱 + 宿主注入 Vue 3 运行时）/ `script`（受限 Python 子进程 + stdio RPC）。
- **生命周期**：上传安装 → 全局启停 → Base 级安装 / 启停 / 移除 → 升级 → 回滚 → 卸载。
- **权限**：manifest 声明 ∩ 用户 RBAC，deny by default，宿主逐方法校验。
- **沙箱**：签名 URL（HMAC-SHA256 + 过期时间）加载 `loader.html`，动态 CSP；脚本沙箱模块白名单（json / re / math / datetime / decimal / collections / itertools / hashlib / base64 / uuid / statistics），移除危险内建。
- **数据通道**：脚本通过 `base.*` 代理回调宿主执行（宿主按触发者身份鉴权）；UI 插件通过 `selection.get()` 获取勾选记录快照（仅记录 ID，上限 1000）。

#### 2.2.14 第三方应用（OAuth2 + 开放 API）

- **模式**：OAuth2 客户端凭证（`client_credentials`），`POST /api/oauth/token` 换取访问令牌。
- **Scope 白名单**：`base:read`、`table:read`、`table:write`、`record:read`、`record:write`、`field:read`。
- **限制**：令牌默认 7200 秒；令牌端点按 `client_id + IP` 限流 60 次/分钟；开放 API 按应用限流 600 次/分钟；读写均落应用审计日志。

#### 2.2.15 通知与邮件

- **站内信**：列表、未读数、详情、标记已读、全部已读、删除；管理端可查日志、统计、重试。
- **邮件**：SMTP 配置校验与测试、模板管理（列表 / 详情 / 更新 / 重置默认）、发送日志、统计、队列统计与清空。
- **降级**：未配置 SMTP 时邮件能力关闭，不影响主流程。

#### 2.2.16 附件与导入导出

- **附件**：上传（≤50MB，扩展名白名单）、元数据、下载、预览、缩略图（图片）、按 Base 列表、删除。存储默认本地 `uploads/`，支持 MinIO（可选）。
- **导入**：Excel / CSV / JSON，预览、分析、执行、任务状态查询；支持多 Sheet 与“分析后直接建表”。
- **导出**：Excel / CSV / JSON，支持按字段与记录子集导出。

#### 2.2.17 审计与配置

- **审计**：操作日志列表与导出（可按用户、时间、动作过滤）；记录级变更历史；插件运行日志；应用审计日志。
- **配置**：公开配置（前端启动读取）、系统配置读写、角色清单、密码策略、注册开关、会话超时等。

#### 2.2.18 地理位置

- **职责**：地图服务配置（天地图 tk 是否配置决定入口是否显示）、中国行政区划树、经纬度反查、国家与地区清单。
- **字段形态**：`geolocation` 类型支持省 / 市 / 区、国家与地区、经纬度、地图选点，多语言显示。

#### 2.2.19 审批

- **职责**：按 Base 查询审批任务、任务详情、通过、驳回、转交、记录审批历史。

## 3. 接口规范

### 3.1 通用约定

#### 3.1.1 基础信息

| 项 | 值 |
|---|---|
| 生产 Base URL | `http://<host>/api`（Nginx 反代到应用 5000 端口） |
| 开发 Base URL | `http://localhost:5000/api`（Vite 侧通过 `/api` 代理） |
| 数据格式 | `application/json; charset=utf-8`（上传为 `multipart/form-data`） |
| 认证 | `Authorization: Bearer <access_token>` |
| 语言协商 | `Accept-Language: zh-CN` / `en-US`（决定 `message` 文案语言） |
| 追踪 | 响应体 `request_id` + 响应头 `X-Request-ID` |
| API 文档 | `/apidocs`（Swagger UI）、`/api/docs.json`（机器可读） |
| 健康检查 | `GET /api/health` |

#### 3.1.2 统一响应格式

**成功**

```json
{
  "success": true,
  "code": 200,
  "message": "获取成功",
  "data": {},
  "meta": {}
}
```

**分页成功**（注意：`data` 直接是数组，分页信息在 `meta.pagination`）

```json
{
  "success": true,
  "code": 200,
  "message": "获取成功",
  "data": [ { "id": "..." } ],
  "meta": {
    "pagination": {
      "page": 1,
      "per_page": 20,
      "total": 137,
      "total_pages": 7,
      "has_next": true,
      "has_prev": false
    }
  }
}
```

**失败**

```json
{
  "success": false,
  "code": 403,
  "message": "您没有权限创建记录",
  "error": "forbidden",
  "details": [{ "field": "values", "message": "字段值不能为空" }],
  "request_id": "9f1c2d3e-..."
}
```

字段说明见 [4.1 通用容器类型](#41-通用容器类型)。

#### 3.1.3 分页与过滤参数

| 参数 | 类型 | 默认 | 约束 | 说明 |
|---|---|---|---|---|
| `page` | integer | 1 | ≥1 | 页码 |
| `per_page` | integer | 20 | 1~500（记录接口上限 500） | 每页条数 |
| `search` | string | — | — | 仅记录列表接口支持，关键词搜索 |
| `size` | integer | 20 / 10 | ≥1 | 历史 / 日志类接口使用 `size` 而非 `per_page` |

> 视图级筛选（`filters`）、排序（`sorts`）、分组（`group_bys`）**不通过查询参数传递**，而是保存在视图配置中由前端执行。

#### 3.1.4 权限等级

接口文档中的权限标注含义：

| 标注 | 判定 |
|---|---|
| 公开 | 无需令牌（分享页、登录、验证码、公开配置） |
| 登录 | 任意已认证用户 |
| `VIEWER` | Base 成员 ≥ viewer，或持有效表分享 |
| `EDITOR` | Base 成员 ≥ editor，或表分享角色为 editor |
| `ADMIN` | Base 成员 ≥ admin |
| `OWNER` | Base 所有者 |
| 系统管理员 | `users.role ∈ {admin, workspace_admin}` |

#### 3.1.5 限流

| 作用域 | 阈值 | 超限响应 |
|---|---|---|
| 查询类接口 | 200 次 / 60 秒 / 用户 | 429 + `error=too_many_requests` |
| 写接口 | 100 次 / 60 秒 / 用户 | 同上 |
| 批量写接口 | 50 次 / 60 秒 / 用户 | 同上 |
| OAuth 令牌端点 | 60 次 / 分钟 / (`client_id`+IP) | 同上 |
| 开放 API | 600 次 / 分钟 / 应用 | 同上 |
| 登录 | 按 IP + 账号独立计数（内存计数，多进程不共享） | 403 / 429 |

#### 3.1.6 并发与幂等

- **文档更新**：`PUT /api/documents/{doc_id}` 传入 `expected_updated_at`，不一致返回 409。
- **记录更新**：服务层支持 `expected_updated_at`（不符抛 `ConflictError` → 409），但当前 `PUT /api/records/{record_id}` 路由未透传该字段，实际并发以“最后写入生效”为主，前端以 `updated_at` 做本地冲突提示。
- **批量接口**：返回 `{updated_count, failed_ids[]}` 形式的部分成功语义，不做整体回滚。
- **重复提交**：创建类接口未做幂等键，重复调用会产生多条数据。

### 3.3 关键接口详细说明

#### 3.3.1 登录

`POST /api/auth/login`

**请求**

```json
{
  "email": "user@example.com",
  "password": "P@ssw0rd!",
  "captcha": "AB3D",
  "captcha_id": "c8f0e2a1-..."
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `email` | string | 是 | 登录邮箱 |
| `password` | string | 是 | 明文口令（HTTPS 传输） |
| `captcha` | string | 视配置 | 验证码答案，系统开启时必填 |
| `captcha_id` | string | 视配置 | 验证码标识，与 `GET /auth/captcha` 配套 |

**成功响应（200）**

```json
{
  "success": true,
  "code": 200,
  "message": "登录成功",
  "data": {
    "user": {
      "id": "3f2b8c1e-9a4d-4f6b-8e2a-1c5d7f9b0a34",
      "email": "user@example.com",
      "name": "张三",
      "avatar": null,
      "role": "editor",
      "status": "active",
      "email_verified": true,
      "must_change_password": false,
      "password_changed_at": "2026-10-01T02:12:00+00:00",
      "last_login_at": "2026-11-09T23:40:11+00:00",
      "created_at": "2026-08-14T07:21:33+00:00",
      "updated_at": "2026-11-09T23:40:11+00:00"
    },
    "tokens": {
      "access_token": "eyJhbGciOi...",
      "refresh_token": "eyJhbGciOi...",
      "token_type": "Bearer",
      "expires_in": 86400
    }
  }
}
```

**演示环境分支（200，需先完成 Gitee 校验）**

```json
{
  "success": true,
  "code": 200,
  "message": "需要先完成 Gitee Star 校验",
  "data": { "requires_gitee_star_check": true, "user_id": "3f2b8c1e-..." }
}
```

**失败**：`401 authentication_failed`（邮箱或密码错误）、`403 captcha_required` / `captcha_invalid`、`429 too_many_requests`。

#### 3.3.2 刷新令牌

`POST /api/auth/refresh`，`Authorization: Bearer <refresh_token>`

```json
{
  "success": true,
  "code": 200,
  "message": "令牌刷新成功",
  "data": { "access_token": "eyJhbGciOi...", "token_type": "Bearer", "expires_in": 86400 }
}
```

前端在收到 401 时会自动调用本接口并重放失败请求（并发请求排队，仅触发一次续期）。

#### 3.3.3 创建记录

`POST /api/tables/{table_id}/records`

**请求**

```json
{
  "values": {
    "a1b2c3d4-0000-0000-0000-000000000001": "产品需求评审",
    "a1b2c3d4-0000-0000-0000-000000000002": 3,
    "a1b2c3d4-0000-0000-0000-000000000003": ["opt_high"],
    "a1b2c3d4-0000-0000-0000-000000000004": "2026-11-20",
    "a1b2c3d4-0000-0000-0000-000000000005": ["u_9f8e7d6c"]
  }
}
```

**字段值形态（`values` 的值取决于字段类型）**：见 [4.5 字段值存储形态](#45-字段值存储形态)。

**成功响应（201）**

```json
{
  "success": true,
  "code": 201,
  "message": "记录创建成功",
  "data": {
    "id": "7c1d9e2f-...",
    "table_id": "b2c3d4e5-...",
    "values": { "a1b2c3d4-...-0001": "产品需求评审" },
    "primary_value": "产品需求评审",
    "created_by": "3f2b8c1e-...",
    "updated_by": "3f2b8c1e-...",
    "created_at": "2026-11-10T14:32:07.123456+00:00",
    "updated_at": "2026-11-10T14:32:07.123456+00:00",
    "computed_values": { "公式字段ID": 1280 }
  }
}
```

**说明**

- 未提供的字段：若有默认值则自动填充；`auto_number` 字段自动生成编号。
- `computed_values` 只包含公式字段，key 为字段 ID（部分跨表场景为字段名）。
- 关联字段写入的是目标记录 ID 数组。

#### 3.3.4 更新记录

`PUT /api/records/{record_id}`

```json
{ "values": { "a1b2c3d4-...-0002": 5 } }
```

响应同创建（200）。语义为**局部合并**：只覆盖 `values` 中出现的字段，未出现的保持不变。

#### 3.3.5 记录分页列表

`GET /api/tables/{table_id}/records?page=1&per_page=200&search=评审`

响应为分页结构（`data` 数组 + `meta.pagination`），每条记录额外携带 `computed_values`；关联字段的 `values[field_id]` 会被填充为目标记录 ID 数组；`lookup` 字段的 `values[field_id]` 为实时计算结果。

#### 3.3.6 创建字段

`POST /api/tables/{table_id}/fields`

```json
{
  "name": "预计工时",
  "type": "number",
  "description": "人天",
  "is_required": false,
  "config": { "precision": 1, "format": "number" },
  "defaultValue": 0
}
```

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `name` | string | 否 | ≤100 字符，缺省「未命名字段」 |
| `type` | string | **是** | 必须在 `FieldType` 枚举内 |
| `description` | string | 否 | — |
| `is_required` | boolean | 否 | 默认 `false` |
| `options` | object | 否 | 选择类字段的选项定义 |
| `config` | object | 否 | 类型相关配置（公式 / 精度 / 关联表等） |
| `defaultValue` | any | 否 | 落库时写入 `config.defaultValue` |

**成功（201）**：`data` 为 `Field` 对象。

`POST /api/tables/{table_id}/views`

```json
{
  "name": "本周待办",
  "type": "kanban",
  "description": "按状态分组",
  "filters": [
    { "fieldId": "f_status", "operator": "isAnyOf", "value": ["opt_todo", "opt_doing"] }
  ],
  "sorts": [ { "fieldId": "f_due", "direction": "asc" } ],
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | 视图名称 |
| `type` | enum | 是 | `table/gallery/kanban/gantt/calendar/form/timeline/list` |
| `description` | string | 否 | — |
| `filters` | array | 否 | 筛选条件数组（结构见 4.3.14） |
| `sorts` | array | 否 | 排序规则数组 |
| `group_bys` | array<string> | 否 | 分组字段 ID |

| `parent_field_id` | uuid | 否 | 层级视图的父字段 |

#### 3.3.8 更新文档（乐观锁）

`PUT /api/documents/{doc_id}`

```json
{
  "name": "周报",
  "content": "{\"ops\":[{\"insert\":\"...\"}]}",
  "content_format": "delta",
  "expected_updated_at": "2026-11-10T14:30:00+00:00"
}
```

- `expected_updated_at` 与库中 `updated_at` 不一致 → **409 Conflict**。
- 比较精度为秒级；不传则跳过校验。

#### 3.3.9 上传附件

`POST /api/attachments/upload`（`multipart/form-data`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `file` | binary | 是 | ≤50MB，扩展名需在 `ALLOWED_EXTENSIONS` 内 |
| `base_id` | uuid | 是 | 归属 Base |
| `record_id` | uuid | 否 | 绑定记录 |
| `field_id` | uuid | 否 | 绑定字段 |

**成功（200）**：`data` 为 `Attachment` 对象；图片会额外生成缩略图并返回 `thumbnail_url`。

#### 3.3.10 导出数据

`POST /api/export/excel`

```json
{
  "table_id": "b2c3d4e5-...",
  "field_ids": ["f1", "f2"],
  "record_ids": ["r1", "r2"],
  "include_headers": true
}
```

响应为文件流（`Content-Disposition: attachment`），非 JSON。`/export/csv`、`/export/json` 结构一致。

#### 3.3.11 发布工作流

`POST /api/workflows/{workflow_id}/publish`

- 前置条件：至少 1 个节点；触发器配置合法。
- 行为：生成 `WorkflowVersion` 快照 → 状态置 `active` → 注册定时任务（若为 `specified_time`）。
- 响应：`data` 含 `workflow` 与 `version` 对象。

#### 3.3.12 插件上传安装

`POST /api/plugins/upload`（`multipart/form-data`，字段 `file` 为 zip）

处理链：zip 安全检查（路径穿越 / zip bomb）→ 解包 → `manifest.json` JSON Schema 校验 → 版本兼容（`engines.smarttable` vs `version.json`）→ 插件 ID / 版本落库 → 包文件归档。

响应 `data` 含 `plugin`、`version`、`action`（`installed` / `upgraded`）。

#### 3.3.13 获取沙箱 URL

`POST /api/plugins/{plugin_id}/sandbox-url`

```json
{
  "success": true,
  "code": 200,
  "message": "获取成功",
  "data": {
    "url": "/api/plugins/com.example.plugin/versions/1.2.0/loader.html?st=1731234567.9f8e...&fst=1731234567.ab12...",
    "expires_in": 300
  }
}
```

`st` 为沙箱令牌，`fst` 为包内静态资源令牌，均为 `HMAC-SHA256(SECRET_KEY)` 签名 + 过期时间。

```json
  "client_id": "app_8f2c1d",
  "client_secret": "secret_...",
```

### 3.4 Socket.IO 事件规范

连接：`io(REALTIME_BASE_URL, { auth: { token: accessToken } })`，服务端校验 JWT 后加入房间。

| 方向 | 事件名 | 载荷 | 说明 |
|---|---|---|---|
| C→S | `room:join` | `{base_id}` | 加入协作房间 |
| C→S | `room:leave` | `{base_id}` | 离开房间 |
| C→S | `presence:view_changed` | `{base_id, view_id}` | 上报当前视图 |
| C→S | `presence:cell_selected` | `{base_id, table_id, record_id, field_id}` | 上报光标位置 |
| C→S | `lock:acquire` | `{base_id, table_id, record_id, field_id}` | 申请单元格锁 |
| C→S | `lock:release` | 同上 | 释放锁 |
| S→C | `presence:user_joined` | `{user_id, name, avatar, socket_id}` | 用户加入 |
| S→C | `presence:user_left` | `{user_id}` | 用户离开 |
| S→C | `lock:acquired` | `{record_id, field_id, user_id, expires_at}` | 锁已获取 |
| S→C | `lock:released` | `{record_id, field_id}` | 锁已释放 |
| S→C | `data:record_created` | `{table_id, record, changed_by, timestamp}` | 记录创建广播 |
| S→C | `data:record_updated` | `{table_id, record_id, changes[], changed_by}` | 记录更新广播 |
| S→C | `data:record_deleted` | `{table_id, record_id, changed_by}` | 记录删除广播 |
| S→C | `data:field_updated` | `{table_id, field}` | 字段变更广播 |
| S→C | `data:view_updated` | `{table_id, view}` | 视图变更广播 |
| S→C | `data:table_updated` / `data:table_created` / `data:table_deleted` | 表对象 / ID | 表变更广播 |

`data:record_updated` 的 `changes` 元素结构：`{field_id, old_value, new_value}`。

### 4.5 字段值存储形态

`records.values` 是 `{field_id: value}`。同一字段类型的值形态必须前后端一致，否则公式与筛选会失效。按类型对照：

| 字段类型 | 存储形态 | 示例 |
|---|---|---|
| 单行/多行/富文本 | `string` | `"需求评审"` |
| 数字/货币/百分比 | `number` | `1299.5`、`0.25` |
| 评分/进度 | `number` | `4`、`65` |
| 日期 | `string` | `"2026-11-20"` |
| 日期时间 | `string` | `"2026-11-20T09:30:00Z"` |
| 单选 | `string[]`（单元素）或 `string` | `["opt_a"]` |
| 多选 | `string[]` | `["opt_a","opt_b"]` |
| 复选框 | `boolean` | `true` |
| 成员 | `string[]`（用户 ID） | `["3f2b8c1e-..."]` |
| 关联 | `string[]`（记录 ID） | `["7c1d9e2f-..."]` |
| 附件 | `string[]` | `["att_001.png"]` |
| 自动编号 | `string` | `"TASK-20261110-0001"` |
| 地理位置 | `object` | `{"province":"浙江省","city":"杭州市","district":"西湖区","lng":120.13,"lat":30.27,"format":"cn"}` |
| 公式 | 不入 `values`，在 `computed_values` | `{"formula_field_id": 1280}` |
| 查找 | 读时回填到 `values[field_id]` | `1280` 或 `"华东"` |
| 创建人/更新人 | `string`（用户 ID） | `"3f2b8c1e-..."` |
| 创建时间/更新时间 | `string`（时间戳） | `"1762774327"` |
| 按钮 | 不存储 | `null` |

### 4.6 字段对齐注意事项

| 现象 | 说明 | 影响 |
|---|---|---|
| `Field.to_dict()` 不含 `is_system` / `is_visible` | 前端 `Field` 类型声明了这两个字段 | 前端需自行按 `type` 推断，勿依赖后端返回 |
| `View.to_dict()` 同时返回 `sorts` 与 `sort_config` | 两者同值，命名历史遗留 | 写入用 `sorts`，读取两者皆可 |
| `group_bys` 与 `group_config` | 前者从后者提取 | 写入任一并保持同步 |
| 分页结构 | `data[]` + `meta.pagination`，不是 `{items,total}` | 前端 `recordApiService` 做了转换，其他调用方需自行适配 |
| `FilterCondition` 字段名 | 前端 `fieldId`，后端查找字段用 `fieldId`，视图存储用数组元素 | 混用 `field_id` 会导致条件失效 |
| `primary_value` | 仅记录接口返回，非 DB 列 | 由主字段实时计算 |
| 时间精度 | 文档乐观锁按秒比较 | 亚秒级差异不触发 409 |

## 5. 错误码说明

### 5.1 错误模型

SmartTable 的错误是**三层结构**，客户端应据此分层处理：

```
HTTP 状态码      → 传输/语义层（401/403/404/409/422/429/500）
error 机器码     → 业务分支（如 email_already_exists、webhook_in_use）
message 文案     → 展示层（i18n key 按 Accept-Language 翻译）
```

- `message` 在服务端是 **i18n key**（如 `no_permission_access_table`），经 `translate()` 翻译后返回。**客户端不要用 `message` 做逻辑判断**，请用 `error` 或 `code`。
- 字段级错误放在 `details[]`（`{field, message, code?}`）。
- 每个失败响应都带 `request_id`，可与服务端日志对齐。

### 5.2 HTTP 状态码

| 状态码 | 语义 | 典型 `error` | 触发场景 |
|---|---|---|---|
| 200 | 成功 | — | 查询、更新、删除成功 |
| 201 | 已创建 | — | 创建 Base / 表 / 字段 / 记录 / 文档 / 视图成功 |
| 400 | 请求参数错误 | `bad_request`、`validation_error` | 缺必填参数、字段名超长、类型不支持、请求体为空 |
| 401 | 未认证 | `unauthorized`、`token_expired`、`token_revoked`、`invalid_token` | 无 Token、Token 过期、Token 被撤销、格式错误、密码错误（登录） |
| 403 | 无权限 | `forbidden`、`permission_denied`、`captcha_required`、`registration_disabled` | 角色不足、非成员、验证码必需、注册关闭、演示环境限制 |
| 404 | 资源不存在 | `not_found` | Base / 表 / 字段 / 记录 / 视图 / 文档 / 工作流 / 插件不存在 |
| 405 | 方法不允许 | `method_not_allowed` | 路径存在但方法不匹配 |
| 409 | 冲突 | `conflict`、`email_already_exists`、`webhook_in_use`、`duplicate_entry` | 邮箱已注册、Webhook 被引用、文档乐观锁失败、唯一约束冲突 |
| 413 | 请求体过大 | — | 超过 `MAX_CONTENT_LENGTH`（默认 50MB） |
| 422 | 校验失败 | `validation_error` | marshmallow 校验不通过，附 `details[]` |
| 429 | 请求过于频繁 | `too_many_requests` | 触发查询/写/登录/OAuth/开放 API 限流 |
| 500 | 服务端错误 | `internal_server_error`、`database_error`、`server_error` | 未捕获异常、数据库异常、依赖缺失（pandas/WeasyPrint 等） |
| 503 | 服务不可用 | `http_error` | 上游依赖不可用 |

### 5.5 校验错误结构

422 与部分 400 响应会带 `details`：

```json
{
  "success": false,
  "code": 422,
  "message": "数据验证失败",
  "error": "validation_error",
  "details": [
    { "field": "email", "message": "邮箱格式不正确" },
    { "field": "password", "message": "密码长度至少 8 位" }
  ],
  "request_id": "9f1c2d3e-..."
}
```

前端 `client.ts` 在 422 时会把 `details[].message` 用换行拼接后统一下发一次 `ElMessage`。

### 5.6 客户端处理约定

| 状态 | 前端行为 | 注意 |
|---|---|---|
| 401（非分享接口） | 自动调用 `/auth/refresh` → 重放队列中的失败请求；失败则清 Token 跳登录 | 已重试过的请求再次 401 不再续期，避免死循环 |
| 401（`skipAuthRedirect`） | 直接拒绝，交由调用方处理（分享页无效 token 是业务错误） | 分享接口需显式设置该标志 |
| 403 | 令牌相关错误 → 清 Token 跳登录；否则仅提示「无权限」 | 判定依据为 `error`/`message` 是否含 token/auth 关键字 |
| 404 | 提示「资源不存在」，不打日志噪音 | — |
| 409 | 提示冲突；文档编辑场景弹出冲突对话框让用户选择保留版本 | — |
| 422 | 逐条展示 `details[].message` | — |
| 429 | 提示「请求过于频繁」并建议稍后重试 | 分享接口不弹提示 |
| 500+ | 提示「服务器错误」或「服务不可用」，并记录 `request_id` 便于排查 | — |

### 5.7 错误码维护约定

1. 新增错误必须同时提供：HTTP 状态码、`error` 机器码、`messages.py` 中的 i18n key（zh-CN + en-US）。
2. `error` 机器码用于客户端分支，一经发布不应改名（改语义需新增码）。
3. 服务端日志必须带 `request_id` 与堆栈；对外响应不得暴露堆栈（`ERROR_SHOW_DETAILS` 默认 false）。
4. 敏感信息（密码、Token、手机号、邮箱）在日志中必须脱敏。
